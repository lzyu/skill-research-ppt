<p>在我们看来，Skill 是经验的可执行形态。它不只是一段提示词，而是一个人经过长期实践形成的知识、判断与方法，被整理成 Agent 可以理解和执行的能力。研究者验证信息的方法、设计师判断取舍的标准、开发者定位问题的路径，都可以成为 Skill。</p>
<p>经验不是静态的，Skill 也会在真实使用中不断生长。新的案例会补充它的知识，失败会暴露能力边界，用户反馈会推动流程和结果持续改进。当这些经验能够被稳定复用，为别人节省时间、降低试错成本并交付结果，它就具备了成为商品的价值。让 Skill 被定价，也是对经验创造者所付出时间与专业判断的尊重。</p>
<p>但开发一个好用的 Skill，和经营一个可以持续收费的 Skill，是两件事。后者还要处理支付、交付、原文保护、试用、订阅与持续履约。支付宝 SkillPay 承接 Skill 分发之后的商品化，让开发者掌握创造与分发，也能从持续产生的价值中获得回报。</p>
<h2 id="01一个-skill-从能用到能卖还差什么">01｜一个 Skill 从“能用”到“能卖”，还差什么？</h2>
<p>以行业研究 Skill 为例，它可能包含开发者长期积累的分析框架、信息筛选方法和任务流程。直接发布完整文件，意味着提示词、工作流和核心方法可能被读取；封装成远程 API，又需要开发者自行处理身份认证、定价、支付、权益和异常恢复。</p>
<p>一个 Skill 真正成为商品，还需要回答一组能力之外的问题：用户购买的是完整文件还是一段时间的使用权，价格和权益如何说明，付款后交付什么，调用失败或权益到期时又该如何处理。这些环节不会让 Skill 本身更聪明，却决定了它能否被放心购买和持续经营。</p>
<p>用户的需求其实很简单：告诉我价格，在我确认后继续完成任务。开发者负责创造和分发，支付宝 SkillPay 负责把后续调用变成可交易、可交付、可持续经营的链路。</p>
<h2 id="02402为-skill-接上付费与任务恢复">02｜402：为 Skill 接上付费与任务恢复</h2>
<p>Agent 可能在执行任务中途触发付费 Skill。此时，支付不应让任务丢失上下文，而应成为一次可识别、确认和恢复的协议握手。</p>
<p>当调用方没有有效权益时，支付宝 SkillPay 返回 HTTP 402 和支付要求；Agent 向用户说明能力与价格，用户付款后，Agent 携带凭证重试原请求。支付宝 SkillPay 再按收费方式完成履约：一次性购买交付完整 Skill，订阅制开放云端保护调用，随后继续原任务。</p>
<p><img src="https://gw.alipayobjects.com/render/p/yuyan/180020010001296536/assets/skillpay-technical-report/02-402-sequence.svg" alt="HTTP 402 在 Agent 调用中的支付时序"></p>
<p>关键不是出现一个付款页面，而是原任务拥有明确的恢复点。没有权益时返回支付要求，权益建立后继续交付，这为开发者提供了清晰的商业边界。</p>
<h2 id="03云端保护防止-skill-明文泄漏">03｜云端保护：防止 Skill 明文泄漏</h2>
<p>Skill 的核心价值往往来自系统指令、专业知识和执行方法。为减少这些内容被直接读取或复制，支付宝 SkillPay 为订阅制 Skill 提供云端保护：完整原文隔离保管，不下载到用户本地。</p>
<p><img src="https://gw.alipayobjects.com/render/p/yuyan/180020010001296536/assets/skillpay-technical-report/03-cloud-protection.svg" alt="支付宝 SkillPay 云端保护与本地执行架构"></p>
<p>每次调用只返回当前任务所需的执行文本，脚本、公开数据和最终答案仍在本地处理。通过最小化披露，既降低核心内容的暴露风险，也保留正常的使用体验。</p>
<h2 id="04当用户要求-agent-交出完整-skill">04｜当用户要求 Agent 交出完整 Skill</h2>
<p>不把完整 Skill 下发到本地，只解决了文件被直接读取的问题。攻击者仍可能通过角色扮演、指令覆盖、编码转换或多轮提问，尝试拼出接近完整的 Skill。</p>
<p>因此，云端保护先理解请求，再把受保护能力收敛为当前任务专用的执行文本，交给本地 Agent 校验和执行，而不是把完整 Skill 当作回答返回。</p>
<p><img src="https://gw.alipayobjects.com/render/p/yuyan/180020010001296536/assets/skillpay-technical-report/04-defense.svg" alt="Skill 云端保护的三类请求处理路径"></p>
<p>正常任务会获得可执行的指导；明显的原文套取会被拒绝，并把对话拉回具体任务；边界请求则在提供必要帮助的同时保持最小披露。保护既要评估是否泄露原文，也要确认正常任务能否正确完成。</p>
<p>我们不会把云端保护描述成绝对不可破解。它是一套由原文隔离、按任务拆分、权限控制、本地校验、审计与回归评测共同构成的持续防御体系，目标是提高批量复制和套取完整 Skill 的成本，同时保持可用性。</p>
<h2 id="05从免费试用到一次性购买与订阅制">05｜从免费试用，到一次性购买与订阅制</h2>
<p>新 Skill 最大的转化障碍往往不是价格，而是不确定性。免费试用让用户用真实任务验证价值，再选择一次性购买或订阅制。</p>
<p>一次性购买交付完整 Skill 源文件，适合永久使用；订阅制提供有效期内的持续使用权益，通过云端保护调用，但不交付完整原文。开发者可以根据 Skill 是否需要持续更新、是否适合完整交付来选择。</p>
<p><img src="https://gw.alipayobjects.com/render/p/yuyan/180020010001296536/assets/skillpay-technical-report/05-business-model.svg" alt="开发者从自主分发、试用转化到持续更新的商业循环"></p>
<p>开发者自主分发，用户通过试用验证价值，再完成购买或订阅；开发者获得回报后持续改进 Skill，让经验与商品一起成长。</p>
