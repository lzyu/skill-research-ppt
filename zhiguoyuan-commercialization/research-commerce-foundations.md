# 智果园 Skill 商业化：可复用交易底座与接入边界

调研日期：2026-10-20。仅查官方公开文档及工作区已保存的官方原始页面；未登录、安装、签约或交易。本文所说“已有”归属于文档对应的云商店或支付产品，**不代表新版 AI 资产广场的 Skill 已集成这些能力**。

## 结论

智果园无需从零建设支付清结算平台。华为云云商店已有商家、商品、订购、交付通知、计费和售后制度，且已有面向 Agent/API 的鉴权计量网关。最有价值的演进，是把 **Skill 的资产 ID、版本、商品 SKU、用户权益、服务调用和订单履约** 接起来。能复用的是交易底座；需要智果园拥有的是 Skill 商业化的产品语义和完整消费闭环。此判断是基于下述公开能力作出的架构建议，尚非已打通的产品承诺。

## 五项最值得复用的官方底座

| 既有能力与归属 | 已核实范围 | 对 Skill 的用法与边界 |
| --- | --- | --- |
| 云商店商品接入及计费 | 通用商品支持多类交付；包周期、买断、套餐等适用范围依商品类型而异；联营 API 商品支持按需、按需套餐包。[S1] | 先明确售卖的是文件授权、周期访问还是远程 API，选择适合的接入方式；不能把所有模式当作每个 Skill 的可选开关。 |
| 云商店 Agents 网关 | API 应用路由、用户鉴权、监控；根据 usage 解析 Tokens、图片数、时长等，或计算请求字节/字符用量。需注册后端、配置鉴权与计费参数、调测后上架；默认北京四。[S2] | 适合“免费 Skill 入口＋付费远程能力”的网关底座。需要补 Skill→SKU→调用主体的映射、失败/重试计费口径；usage 计量不等于任务成功验收。 |
| SaaS 订购后交付接口 | 云商店续费或试用转正后通知商家延长实例；失败可重试；商家必须按订单做幂等。续费、退续费会产生新订单，实例 ID 才是稳定资源标识。[S3] | 可借用订购事件与交付消息机制，适配“授权期限、席位、额度、租户”权益；原有 SaaS 实例不是 Skill 安装态或保护执行态。 |
| 华为支付入网与分账 | 2026-03-31 起通用商品升级华为支付；商家需入网，客户款项直接进入商家账户，云商店提供结算规则/金额，由华为支付向相关方结算分账。[S4] | 复用商户合规、收款与分账，避免智果园自建资金账户。云商店扫码支付并不等于 Agent 内 AI 支付，亦不等于微信 AI 专属卡。 |
| 云商店退订及发票制度 | 退订按接入方式/计费类型/验收状态区分；开通失败支持自动全额退款；API 等存在不支持退订场景。通用商品发票由服务商提供。[S5] | 可复用售后渠道与单据，但需为源码已交付、订阅已生效、调用失败、结果未交付分别制定清晰规则，不能统一承诺“失败即退”或照搬普通 SaaS 退订。 |

### 特别需要避免的归属错误

云商店官方“AI 资产类”指基于 ModelArts、HoloSens 等平台得到的算法、模型、工程，而非自动涵盖当前 Skill 包。[S1] 因此“华为已经支持 AI 资产收费”只能说明邻近商业底座存在，不能证明新版 Skill 广场已经具备版本授权、付费安装、云端保护或运行计费。

## 三层复用决策

| 分类 | 建议能力 | 上线前的明确条件 |
| --- | --- | --- |
| 沿用制度/已有服务 | 云商店商家入驻、商品审核与协议、收付款及分账、发票、退款渠道 | 确认 Skill 商品类型、通用/联营模式、责任主体及费率；“沿用”不表示跳过入网和产品接入。 |
| 适配后复用 | 商品 SKU/价格、订购与续期通知、Agents 网关鉴权计量、对账与售后工单 | 连接 asset_id/version→product_id/SKU→instance/entitlement→execution_id/order_id；实现签名验真、幂等、重试、失效回收及对账。 |
| 智果园必须拥有 | Skill 售卖契约、许可/版本权益、试用配额、兼容安装及调用授权；任务状态与交付凭证；跨宿主恢复；付费场景质量和经营漏斗 | 可自研或采购，但平台必须给出统一规则并负责编排。支付渠道不会代替这些业务能力。 |

优先建议：先上线**免费包＋付费远程服务**，利用可控制的服务端完成鉴权、计量和结果交付；再扩展源码买断、受保护订阅。源码下载后不能只靠支付网关实现持续使用控制；受保护订阅需要另外建设服务端保护和本地执行协作。这是产品顺序建议，不是现网状态断言。

## 阿里、微信能力能否直接接入智果园

### MachinePay：具备外部服务商接入路径，但不是 Skill 商业平台成品

支付宝正式接入指南明确支持自研商家/服务商通过自研应用，或第三方应用代调用（app_auth_token）接入。商家需返回 402 账单、验支付凭证并发送履约回执。[S6] 因此它可以作为智果园外部收款通道的候选，而非只限支付宝自己的 Skill 广场。

但“协议可接”与“智果园用户可用”是两件事：仍需商家/三方应用签约、服务登记，消费宿主接入付款能力和用户授权，以及智果园自己的订单、权益、交付与异常恢复。公开资料不足以确认智果园已获准的平台模式、宿主支持、费率、结算规则。**支付宝 SkillPay 的受保护订阅/云端保护与本地执行协作是否以开放服务供第三方平台调用，也未得到公开接口的确证**，不能写成直接可拿来用的 SDK。

### 微信 AI 支付：现行官方路径包含 SkillHub，与普通微信扫码应分开

微信官方开发准备明确要求支持的商户资质，流程包含 SkillHub 企业认证、开通 SkillPay、绑定商户号并取得开发者密钥。当前发布上架路径由 SkillHub 分发。官方指南要求消费智能体实际存在名称含 weixinpay_ 的支付工具；不支持时不能先下单。回调/查单及退款沿用传统微信支付。[S7]

这证明可借鉴其“商户认证＋身份密钥＋宿主支付插件＋后台验款”的方法，但**尚不能证明智果园可以绕过 SkillHub，独立以相同 AI 支付协议接入**。如果选微信 AI 支付，需向渠道确认第三方平台合作、身份签发/验签、宿主工具授权和协议版本。若仅通过云商店华为支付页面使用微信扫码，那是既有支付渠道，不能宣传为已支持微信 AI 专属卡或 Agent 自动拉起。

## 建议写入两页材料的关键话语

1. **阿里做好“卖什么与如何交付”：源码买断、受保护订阅、试用权益；MachinePay 将资源付费纳入 Agent 请求。腾讯做好“商家如何进来并完成交易”：认证、密钥、分发与微信支付宿主协同。**
2. **智果园优先把现有分发与云商店交易连接成 Skill 闭环：复用收款结算，补齐商品权益、用量/结果账本和支付后恢复。**
3. **不是所有能力都能直接接：云商店接入依商品/合作模式；第三方 AI 支付依签约和宿主能力；云端保护不是通用支付接口自带。**

以上跨平台话语须与主报告的阿里/腾讯原始证据共同使用。本文重点证实华为邻近基础设施及外部接入边界。
