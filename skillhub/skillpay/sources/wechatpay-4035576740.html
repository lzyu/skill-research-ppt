x402预下单

更新时间：2026.09.01
||| 安装 Skill

Agent 触发 x402 支付的场景下，服务开发者需调用该接口在微信支付侧完成预下单，生成用于触发支付的一次性支付凭证(payment_code)。

接口说明

支持调用方：【SKILLHUB 服务开发者】

请求方式：【POST】/aipay/preorder

请求域名：【主域名】https://aipay.wxpapp.weixin.qq.com

请求参数
折叠全部参数

Header  HTTP头参数

 Authorization 　必填　string

请参考本文「签名指引」章节生成认证信息，认证类型固定填 SKILLHUB-SHA256-RSA2048。

 Accept 　必填　string

请设置为application/json

 Content-Type 　必填　string

请设置为application/json

 BODY  包体参数

 payment_required 　必填  object

【预下单信息】x402 预下单的业务信息主体，所有业务字段均包含在该对象内。

属性

 skill_info  　必填  object

【Skill 信息】Skill 信息对象。SKILLHUB 平台必填。

属性

 skill_id 　必填   string(64)

【Skill 标识】Skill 标识，对应 Skill 定义中的 name。SKILLHUB 平台必填。

 skill_version 　必填  string(64)

【Skill 版本号】Skill 的版本号。SKILLHUB 平台必填。示例：1.0.0

 pay_type  　必填  string

【支付类型】当前支持的取值：

  • GOODS_PAY：商品付费，即按商业支付订单付费。

 pay_mode 　必填  string

【付费方式】当前支持的取值：

  • AUTH_AND_PAY：授权即支付，当前仅支持该方式。

 expires_at 　必填   string

【授权超时时间】Unix 秒级时间戳字符串，用户须在该时间之前完成授权，最长 15 分钟。该时间同时作为应答返回的 payment_code 的有效期（仅为请求字段，应答不回显）。示例：1747901100

 pay_items 　必填  array[object]

【支付信息列表】支付信息列表，至少传入 1 条。

属性

product_id 　必填  string(64)

【产品标识】产品标识。SKILLHUB 平台必填。

 pay_data 　必填  object

【支付信息】支付信息对象。

属性

type 　必填  string

【支付信息类型】支持的取值：code_url / prepay_id / h5_url。

 value 　必填   string(64)

【支付信息内容】按 type 填入对应下单接口的返回值。

请求示例

POST

1curl -X POST \
2  https://aipay.wxpapp.weixin.qq.com/aipay/preorder \
3  -H "Authorization: SKILLHUB-SHA256-RSA2048 developer_platform=\"SKILLHUB\",developer_id=\"dev_1234567890\",pub_key_id=\"PUBKEY_ABC001\",nonce_str=\"a1b2c3d4e5f60718\",timestamp=\"1747900200\",signature=\"MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...\"" \
4  -H "Accept: application/json" \
5  -H "Content-Type: application/json" \
6  -d '{
7    "payment_required" : {
8      "skill_info" : {
9        "skill_id" : "skill_id",
10        "skill_version" : "1.0.0"
11      },
12      "pay_type" : "GOODS_PAY",
13      "pay_mode" : "AUTH_AND_PAY",
14      "expires_at" : "1754208460",
15      "pay_items" : [
16        {
17          "product_id" : "product_id",
18          "pay_data" : {
19            "type" : "prepay_id",
20            "value" : "wx201410272009395522657a690389285100"
21          }
22        }
23      ]
24    }
25  }'

应答参数

200 OK

 payment_code  　必填   string(64)

【一次性支付凭证】用于触发支付的一次性凭证。有效期对应请求传入的 expires_at（最长 15 分钟）；凭证过期或已被使用后，需重新调用本接口获取新的 payment_code。

应答示例

200 OK

1{
2  "payment_code" : "xY9zAbc123def456"
3}

接口执行出错时，返回如下结构的错误应答：

 code 　必填  string(32)

【错误码】标识错误类型的错误码。

 message 　必填  string(256)

【错误描述】错误的详细描述信息。

错误应答示例

1{
2  "code" : "SYSTEM_ERROR",
3  "message" : "系统异常，请稍后重试"
4}

签名指引

本接口使用密钥提供方（developer_platform）分配的密钥签名，签名方式与微信支付 v3 API 一致。

构造待签名串

签名串由 5 行组成，每行以 \n 结尾（包括最后一行）：

1HTTP请求方法\n
2URL\n
3请求时间戳\n
4请求随机串\n
5请求报文主体\n

具体到预下单接口：

行

内容

说明

 第 1 行

 POST

 HTTP 请求方法

 第 2 行

 /aipay/preorder

 接口 URL 路径

 第 3 行

 timestamp

 时间戳字符串原值

 第 4 行

 nonce_str

 随机串原值

 第 5 行

 请求报文主体

 请求报文主体

计算签名

示例（伪代码）：

1signature = Base64( RSA_Sign( developer_private_key, SHA256(sign_string_bytes) ) )

  • 算法：使用密钥提供方（developer_platform）分配的密钥做非对称签名；具体算法标识填入 signature_type。

  • 密钥：密钥提供方为该开发者分配的密钥（与 pub_key_id 公钥 ID 配对）。

  • 输出：Base64 编码字符串。

构造 Authorization 头

1Authorization: <认证类型> <签名值>

认证类型目前只支持 SKILLHUB-SHA256-RSA2048，签名值为多个 key="value" 以英文逗号拼接的字符串。

Key

说明

 developer_platform

 支持 SKILLHUB，按实际的密钥提供方填写

 developer_id

 根据 developer_platform 填入对应平台颁发的 Id

 pub_key_id

 按 developer_platform 对应填写：其分配的公钥 ID，对应其签名所用的密钥（无证书，使用公钥 ID 标识）

 nonce_str

 随机串，参与签名，每次请求须唯一，建议长度 16~32 字符

 timestamp

 Unix 时间戳秒级字符串，参与签名，表示签名生成时刻。示例："1747900200"

 signature

 用 developer_platform 对应分配的密钥对上述签名串做非对称签名，Base64 编码

示例值：

1Authorization: SKILLHUB-SHA256-RSA2048 developer_platform="SKILLHUB",developer_id="dev_1234567890",pub_key_id="PUBKEY_ABC001",nonce_str="a1b2c3d4e5f60718",timestamp="1747900200",signature="MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA..."

错误码

出错时 HTTP 状态码也会相应变化：4xx 代表逻辑错误（如参数校验失败、签名错误、鉴权失败等），5xx 代表系统错误（如后台服务异常）。

状态码

错误码

描述

解决方案

 4xx

 逻辑错误类错误码

 参数校验失败、签名错误、鉴权失败等

 请根据应答中的 code 与 message 检查请求参数与签名

 5xx

 SYSTEM_ERROR

 系统异常，请稍后重试

 请稍后使用相同参数重新调用
