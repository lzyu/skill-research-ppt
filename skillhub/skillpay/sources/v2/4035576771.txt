安装 Skill
产品相关问题
Q1：商户是否需要直接对接各智能体平台？
A：不需要。商户只需在 SkillHub 完成入驻并上架 Skill，由 SkillHub 代替商户接入各智能体平台。
Q2：我已经接入了微信支付，接入 AI 支付还需要做哪些增量工作？
A：需完成下面两件事：
1、在现有下单流程之后新增一步 x402 下单；
2、开发并上架商户 Skill（见《
开发指引
》2.2）。
现有的传统下单流程保留不变，x402 下单与传统下单是串联关系，传统下单产生预支付标识（code_url / prepay_id / h5_url），x402 下单再将其登记到微信 AI 支付后台，转换为智能体内可拉起的支付凭据，因此两步缺一不可；缺传统下单则无单可付，缺 x402 下单则智能体无法拉起支付。
Q3：支付成功后，商户如何感知支付结果？
A：AI 支付沿用传统微信支付的支付结果通知（notify_url）与查单接口，商户无需额外对接。商户应以自身后台的支付回调 / 查单结果作为发货依据，不要依赖智能体对话内容判断支付是否成功。
Q4：退款如何处理？
A：沿用传统微信支付退款接口，AI 支付侧无需额外操作。
Q5：用户尚未开通微信支付AI专属卡时会发生什么？
A：智能体会自动引导用户先完成微信支付AI专属卡的开通与绑定，再继续支付流程，商户侧无需特殊处理。
Q6：用户在支付卡片上取消支付（或超时未支付）后怎么办？
A：商户无需重新下单。payment_code 凭据的有效期为 15 分钟，有效期内用户可在智能体内对同一笔订单重新发起支付；若凭据已过期，则需重新走下单流程。
Q7：我有其他接入相关的问题，如何联系到相关业务同学？
A：可以编辑邮件并发送至
aipay@tencent.com
，收到邮件后业务团队同学将根据你的需求进行回复。
x402接口相关问题
Q1：HTTP 402 和 200 两种触发方式分别适用什么场景？
A：payment_code（即通过 WeixinPay-Required 投递的支付凭据）通过 HTTP Header 投递时支持两种状态码：
402 模式
：服务返回 HTTP 402 状态码并携带 WeixinPay-Required Header。
200 模式（兼容模式）
：服务返回 HTTP 200 + WeixinPay-Required Header。适用于不允许自定义 HTTP 状态码的平台（如某些 Serverless 框架、API Gateway），或中间件会将 4xx 响应视为错误拦截的场景。
两种模式下 Agent 侧统一以 WeixinPay-Required Header 是否存在作为判定依据。
关于只读 body 的 Agent
：部分 Agent 的工具链只把响应体喂给模型、丢弃响应头，读不到 WeixinPay-Required 头。因此
建议在返回 WeixinPay-Required 响应头的同时
，在响应体内附加独立、可剥离的 WeixinPay 提示块（含 WeixinPay-Required + prompt），与业务内容隔离、不侵入业务字段；响应头与响应体双投递，一份响应同时兼容读头与只读 body 两类 Agent。
双投递示例（提示块具体字段格式以 API 接口文档为准）：
1
HTTP/1.1 402 Payment Required
2
WeixinPay-Required: <payment_code>
3
4
{
5
"data": { ...业务字段照常... },
6
"WeixinPay-Required": "<payment_code，与响应头一致>"
7
}
两点需要注意
：
响应体中的凭据必须与响应头
逐字节一致
，不得截断、换行、转义或二次编码——凭据被改写是支付拉起失败最常见的原因之一。
部分 CDN / API 网关 / 企业代理会
剥离自定义响应头
。若自测时"明明返回了 Header 却拉不起支付"，请先检查凭据是否被链路上的中间件丢弃；双投递同时也是对这类中间件的保险。
Q2：pay_data.type 该选哪个？分别对应什么下单接口？
A：根据已接入的微信支付下单方式选择，下单返回值原样填入 pay_data.value：
pay_data.type
来源下单接口
value 示例
code_url
Native 下单
POST /v3/pay/transactions/native
weixin://wxpay/bizpayurl?pr=xxx
prepay_id
JSAPI / 小程序下单
POST /v3/pay/transactions/jsapi
APP 下单
POST /v3/pay/transactions/app
wx201410272009395522657a690389285100
h5_url
H5 下单
POST /v3/pay/transactions/h5
https://wx.tenpay.com/cgi-bin/mmpayweb-bin/checkmweb?prepay_id=...&package=...
Skill开发相关问题
Q1：为什么我的 Skill 无法成功在智能体内拉起 AI 支付？
A：按可能性从高到低排查：
工具 / 脚本的输出中是否包含支付凭据
原文
：
WeixinPay-Required: xxx
或
{ "WeixinPay-Required": "xxx" }
。
凭据是否被模型转述、截断或改写——凭据必须出现在
工具返回值
中，靠模型在回复里复述是不可靠的。建议在 SKILL.md 中明确要求：将下单返回原样输出，不要改写、省略或总结 WeixinPay-Required 字段。
当前智能体是否支持微信 AI 支付——参见《
开发指引
》2.2.1 的前置检查。
凭据是否已过期（payment_code 有效期为 15 分钟），过期需重新下单。
Q2：支付发起后，Skill 还需要做什么？
A：智能体侧无需再做任何操作：支付卡片弹出后由用户在卡片上确认完成，Skill 不应在对话内反复查询支付状态或重复发起支付。商户后台照常通过支付回调 / 轮询查单获知订单终态，并据此驱动发货等后续业务。
