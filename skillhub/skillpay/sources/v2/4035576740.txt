Agent 触发 x402 支付的场景下，服务开发者需调用该接口在微信支付侧完成预下单，生成用于触发支付的一次性支付凭证(payment_code)。

签名指引
本接口使用密钥提供方（developer_platform）分配的密钥签名，签名方式与微信支付 v3 API 一致。
构造待签名串
签名串由 5 行组成，每行以
\n
结尾（
包括最后一行
）：
1
HTTP请求方法\n
2
URL\n
3
请求时间戳\n
4
请求随机串\n
5
请求报文主体\n
具体到预下单接口：
行
内容
说明
第 1 行
POST
HTTP 请求方法
第 2 行
/aipay/preorder
接口 URL 路径
第 3 行
timestamp
时间戳字符串原值
第 4 行
nonce_str
随机串原值
第 5 行
请求报文主体
请求报文主体
计算签名
示例（伪代码）：
1
signature = Base64( RSA_Sign( developer_private_key, SHA256(sign_string_bytes) ) )
算法：使用密钥提供方（developer_platform）分配的密钥做非对称签名；具体算法标识填入 signature_type。
密钥：密钥提供方为该开发者分配的密钥（与 pub_key_id 公钥 ID 配对）。
输出：Base64 编码字符串。
构造 Authorization 头
1
Authorization: <认证类型> <签名值>
认证类型目前只支持
SKILLHUB-SHA256-RSA2048
，签名值为多个 key="value" 以英文逗号拼接的字符串。
Key
说明
developer_platform
支持 SKILLHUB，按实际的密钥提供方填写
developer_id
根据 developer_platform 填入对应平台颁发的 Id
pub_key_id
按 developer_platform 对应填写：其分配的公钥 ID，对应其签名所用的密钥（无证书，使用公钥 ID 标识）
nonce_str
随机串，参与签名，每次请求须唯一，建议长度 16~32 字符
timestamp
Unix 时间戳秒级字符串，参与签名，表示签名生成时刻。示例："1747900200"
signature
用 developer_platform 对应分配的密钥对上述签名串做非对称签名，Base64 编码
示例值：
1
Authorization: SKILLHUB-SHA256-RSA2048 developer_platform="SKILLHUB",developer_id="dev_1234567890",pub_key_id="PUBKEY_ABC001",nonce_str="a1b2c3d4e5f60718",timestamp="1747900200",signature="MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA..."
错误码
出错时 HTTP 状态码也会相应变化：
4xx 代表逻辑错误
（如参数校验失败、签名错误、鉴权失败等），
5xx 代表系统错误
（如后台服务异常）。
