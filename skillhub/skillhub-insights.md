# 腾讯 SkillHub 平台洞察：定位、资产、消费、生态与评测

调研日期：2026 年 10 月 19 日。主要依据腾讯官方仓库、公开 API 实际响应、官网当前发布的页面代码及教程。消费分析采用下载榜前 50 条公开记录，统计文件与原始响应保存在本目录。

## 1. 核心判断

**SkillHub 正由面向中国用户的 Skill 获取入口，扩展为连接全球供给、本土创作者、企业服务和 Agent 消费入口的能力平台。其竞争重点是供给组织、国内可获取性、质量与安全信号，以及安装到使用的衔接。**

官方仓库将全球同步、本土发布、安全认证、TRACE、企业发布及内部技能库列为主要能力。当前官网导航还提供专家包、MCP、SOUL 和插件等入口，表明平台承载的对象已经超出单个 Skill。[官方仓库](https://github.com/Tencent/skillhub)、[官网](https://skillhub.cn/)

这一定位可分为三部分理解：

- **供给侧：** 通过全球同步扩大覆盖，通过本土作者与企业发布补充中文及专业服务。
- **平台侧：** 组织搜索、分类、版本、质量报告、安全报告及组织可见性。
- **消费侧：** 同时服务网页选购式发现、CLI 安装、API 集成和 Agent 宿主内消费，并增加云端运行案例能力。

这里的“扩展为能力平台”是根据产品能力作出的分析判断，不是对商业效果或用户规模的证明。

## 2. 资产定位与结构：用四层分析视图理解

四层是本稿为了说明职责而建立的分析视图。官网提供相应对象入口，但没有把它们定义成一套强制依赖的四层架构。

| 分析层 | 主要资产 | 面向的需求 | 与其他层的关系 |
| --- | --- | --- | --- |
| 角色层 | SOUL / Soul.md | 规定人格、表达和协作方式 | 为 Agent 提供行为与风格配置，可以与技能组合 |
| 场景组合层 | 专家包 / 技能包 | 围绕一个工作场景获取多项能力 | 聚合多个 Skills，减少逐项选择成本 |
| 任务方法层 | Skill | 完成具体任务的方法与资源 | 指令结合脚本、参考资料和模板，按需使用工具 |
| 工具服务层 | MCP Server / 外部 API | 访问真实数据、执行受控动作 | 提供工具接口、服务及连接，仍需处理鉴权和运行条件 |

官网导航分别指向 `/soul`、`/skillspackage`、`/skills` 和 `/mcp`；官方说明也提及 Soul.md 与行业技能包。插件可作为跨层组合的交付容器，不宜再混成一个 Skill 类型。[官网](https://skillhub.cn/)、[官方产品说明](https://github.com/Tencent/skillhub#什么是-skillhub)

### Skill 本体与平台记录

资产文件与平台元数据分开理解：Skill 文件承载任务方法；平台记录负责来源、版本、作者、分类、依赖标签、热度、评测和安全信息。公开文件接口还提供文件列表与内容摘要，支持安装前检查和内容核验。[文件接口](https://github.com/Tencent/skillhub/blob/main/docs/api/files.md)

```text
Skill 内容：SKILL.md + 可选脚本、参考资料、模板
平台记录：来源、作者、版本、分类、依赖、热度、质量、安全
安装实例：某个版本在某个宿主中的内容和连接状态
运行案例：某次输入、对话、工具调用与生成结果
```

这四类信息对应不同的管理问题。一个热度高的详情页，不能代替目标环境中的成功运行证据。

## 3. 资产消费：来源、发布、消费与试运行

### 3.1 来源：全球同步、本土共建和企业服务并存

官方仓库声明持续同步包括 ClawHub 在内的全球 Skills，并支持作者和组织自行发布。实际下载榜样本中的来源标签包括 `clawhub`、`community` 和 `enterprise`。[官方仓库](https://github.com/Tencent/skillhub)、[本次下载榜接口](https://api.skillhub.cn/api/skills?sortBy=downloads&order=desc&pageSize=50)

应把“来源渠道”“发布者身份”和“任务领域”分开：

- 来源渠道说明同步或发布路径。
- 发布者身份说明平台团队、企业、个人或社区作者。
- 任务领域说明办公、开发、行业数据等能力方向。

例如，平台维护的 `find-skill-skillhub` 在当前 API 中标为 `community`，腾讯文档标为 `enterprise`。因此，不能仅用 `source=official` 统计腾讯官方供给，也不能把企业供给全部等同于垂直行业供给。[平台维护 Skill](https://github.com/Tencent/skillhub/tree/main/skills)、[腾讯文档详情](https://api.skillhub.cn/api/v1/skills/tencent-docs)

### 3.2 发布：内容接入、版本与组织审核

官方资料列出发布、GitHub 导入、版本及可见性管理；组织成员可以管理内部 Skill。官网教程还提供文件上传及团队发布流程。[Open API 总览](https://github.com/Tencent/skillhub/blob/main/docs/README.md)、[官网教程](https://skillhub.cn/tutorials)

团队发布教程描述的流程是：提交后自动安全审核，再进入团队管理员审核；管理员审核可按配置自动进行。未通过的版本需要修改后重提。这是团队发布场景的流程说明，不宜直接推广为所有来源同步和发布渠道的统一时效承诺。

**体验判断：** 企业认证和团队私有库有利于把公共社区与组织内部复用放在同一平台；发布方仍需要让版本、授权、依赖和效果案例保持一致。

### 3.3 消费：网页发现与 Agent 入口并行

| 入口 | 已核对的能力 | 对使用体验的意义 |
| --- | --- | --- |
| Web | 中文检索、分类、榜单、详情和报告 | 降低发现和选择成本 |
| CLI | 搜索、安装、发布、校验等 | 在终端完成获取与管理 |
| ZIP / 版本下载 | 指定版本或 tag 下载文件包 | 支持显式版本选择与人工部署 |
| Open API | 列表、详情、文件、版本差异和质量结果 | 可嵌入企业门户、IDE 或自有 Agent 产品 |
| DSH 插件 | 对话中搜索、查看详情、选择版本及本地安装 | 减少离开宿主操作的步骤 |

来源：[官方 API 说明](https://github.com/Tencent/skillhub/blob/main/docs/README.md)、[DSH 插件说明](https://github.com/Tencent/skillhub/blob/main/dsh-plugin/README.md)。

**体验判断：** SkillHub 将“发现能力”延伸到“在宿主里获得能力”，但安装仍需处理依赖、账号、网络和权限。国内下载优化也不能直接证明所有外部 API 都可用。

### 3.4 试运行：具备云端运行与案例链路，但本稿未执行

官方仓库列出沙箱、会话、流式输出和文件处理能力。官网当前生产代码存在沙箱会话创建、恢复、加载 Skill、历史会话、流式结果和运行案例组件，支撑“云端运行并展示案例”的产品链路。[官方能力说明](https://github.com/Tencent/skillhub/blob/main/docs/README.md)、[官网](https://skillhub.cn/)

相较只有说明和下载，运行案例可以展示输入、对话、工具调用及结果，帮助使用者判断是否适合自己的任务。但仍需核对案例对应的版本、模型、输入和连接条件，才能用于效果比较。

本次只核查公开文档、接口和前端实现，没有登录、创建沙箱会话或执行 Skill。因此没有对运行成功率、耗时、隔离效果、费用或产出质量作实测结论。

## 5. 评测机制：把四类信号分开

| 信号 | 表达什么 | 不应直接推导什么 |
| --- | --- | --- |
| 下载、收藏、安装 | 获取与互动的记录 | 真实任务成功率、用户活跃度 |
| 榜单 `score` | 用于排序的综合热度 | TRACE 五分制质量得分 |
| TRACE | 五维质量及子项解释 | 所有场景均经过动态运行验证 |
| 安全报告 | 对应扫描或认证结果 | 无条件安全、账号已授权或任务一定成功 |

公开列表接口将 `score` 定义为排序用值；质量接口另外返回五个维度和公开解释，应在产品界面及数据分析中分别使用。[列表字段](https://github.com/Tencent/skillhub/blob/main/docs/api/skills.md)、[质量接口](https://github.com/Tencent/skillhub/blob/main/docs/api/evaluation.md)

### 5.1 TRACE 的五个维度

| 维度 | 关注问题 |
| --- | --- |
| Trust 可信度 | 来源、安全与国内环境可用性 |
| Reliability 可靠性 | 功能、稳定性和异常处理 |
| Adaptability 适应性 | 触发条件与适用边界 |
| Convention 规范性 | 结构、渐进加载、文档与常见问题 |
| Effectiveness 有效性 | 准确性、完整性、可用性和创新性 |

当前公开细则合计 15 个子项，子项满分 5 分，未评估可以为 `null`；接口文档要求按“先计算维度均分，再计算五维均分”形成展示总分。官网教程中的等级说明属于展示分级，不等同于发布阻断阈值。[质量接口与计算方式](https://github.com/Tencent/skillhub/blob/main/docs/api/evaluation.md)

### 5.2 安全审核、开源 evaluator 与运行评测不同

官网团队发布教程描述自动安全审核；详情样本实际返回两路安全报告。开源 TRACE evaluator 则是 Agent 可使用的评测方法：它明确跳过 `trust.scan`，并允许根据流程和模板检查文档型 Skill 的有效性。因此，不能把开源 evaluator 当作平台安全扫描器，也不能把每个有效性分数都解释为功能实测。[官网教程](https://skillhub.cn/tutorials#trace-evaluation)、[开源 evaluator](https://github.com/Tencent/skillhub/tree/main/skills/skillhub-trace-evaluator)

更深入的评分结构、单样本异常和试运行证据见同目录[评测与运行子调研](./research-evaluation-runtime.md)。

### 5.3 抽查发现：评测结果仍需核对目标身份与版本

本次查询 `find-skill-skillhub` 时，详情功能为技能检索，而对应评测响应中的部分解释围绕日志处理。两者存在内容不一致，原始响应已保存。尚未查明是映射、缓存、历史版本还是其他原因，不能用一个样本推算全站错误率。[详情](https://api.skillhub.cn/api/v1/skills/find-skill-skillhub)、[评测响应](https://api.skillhub.cn/api/v1/skills/find-skill-skillhub/evaluation)

这项观察对平台建设的启示是：让资产身份、内容摘要、版本、评测任务和报告可以互相追溯，并抽查解释是否与实际包内容一致。

## 6. 体验洞察与平台建设启示

### 已有价值

1. **发现更接近任务。** 中文搜索、专业专区和场景组合，让使用者可以从业务目标出发选择能力。
2. **消费入口贴近宿主。** CLI、API 与 DSH 插件分别覆盖个人终端、自有产品和对话内消费。
3. **增加决策证据。** 版本、文件、TRACE、安全报告及运行案例，可帮助使用者从名称判断走向内容与证据判断。
4. **供给从开源目录延伸到企业服务。** 专业数据和业务接口以 Skill 形式进入 Agent 任务，拓展了资产平台的服务连接价值。

### 值得继续核查

- 规模、来源、安装和下载口径能否一致解释并持续披露。
- 运行案例、TRACE 结果与实际 Skill 版本能否可靠关联。
- 从试运行到本地使用，依赖、授权及输入条件是否能一起迁移。
- 专家包是否提供组合版本、工具依赖和整条流程验收，而不仅是批量安装。
- 专业服务的适用边界、数据访问和实际任务效果能否在消费前清楚表达。

### 对本项目的建议

优先借鉴“多类资产协同 + 宿主内消费 + 质量证据”的组织方式。平台建设时同时管理来源版本、安装条件和任务结果；将社区覆盖度、企业供给深度、任务消费效果作为不同目标衡量。

## 7. 数据与验证范围

- 调研为公开资料与只读接口观察，没有安装外部 Skill，没有发布、购买、授权或创建线上运行会话。
- 官网浏览器载入超时，体验判断主要依据官方文档与当前生产代码；没有将页面代码存在等同于端到端操作成功。
- 快照中的条目按 API 返回记录统计，保留作者维度；相同 slug 可能出现不同作者，未按 slug 强行去重。
- 详细统计见 `statistics.json`，下载榜样本见 `download-top50.csv`，原始资料及 URL 清单见 `sources/`。
- 官方仓库、当前页面、实际接口和本稿分析推断在文中分别标明；不采用社区文章中缺乏同口径证据的规模或效率数字。
