SKILL LIFECYCLE · 四段实际做法

一个 Skill 的四段路：写出来 → 发出去 → 装进去 → 用起来

Skill 以 SKILL.md 为入口，按需配脚本 / 资料 / 模板；四段路各有具体做法，用完的反馈再回到生产。

01

生产

PRODUCE

把一次做对的过程写下来

  • SKILL.md：name、description，
    正文写步骤、异常与验收
  • 跑 $skill-creator 生成草稿，
    再拿真实任务改
  • 现成 MCP / API / SOP
    封装成方法，并声明依赖
  • 用「该用 / 不该用 / 边界」
    三类任务验证触发与结果
  • 留一个能跑通的样例，
    再写清不适用的情况
产物SKILL.md + scripts/
references/ + 评测记录
02

分发

DISTRIBUTE

把确定的版本交到手上

  • Git 仓库：目录 + 提交历史，
    ref 指向实际 commit
  • ZIP / 目录包：离线交付，
    附依赖与完整性说明
  • 市场目录（如 Skills.sh）做发现，
    CLI 负责取
  • Plugin：plugin.json + skills/
    + mcp.json 组合交付
  • 托管 API：上传 ZIP，返回
    skill_id + version
产物发布包 + 来源 / 版本 / 许可
Plugin 另含 mcp.json
03

安装

INSTALL

让宿主发现并跑得起来

  • 复制到 ~/.claude/skills/、
    ~/.agents/skills/（也可项目级）
  • CLI：npx skills add <repo>
    --skill <name> -g -a codex
  • Agent 内：$skill-installer
    从指定仓库装，并报位置
  • 云端：skill_reference
    挂 skill_id + version
  • 查依赖与权限，
    跑一个最小任务验证
产物安装实例 + 就绪检查
记下宿主、作用域、版本
04

使用

USE

选中、加载，交付结果

  • 提目标、输入、约束和验收；
    Agent 按 description 选
  • 点名：Claude 用 /pdf-processing
    Codex 用 $pdf-processing
  • 渐进加载：目录 → SKILL.md →
    按需读 references/、跑 scripts/
  • 执行后验收，记录版本、
    环境与修正
  • 结果不合格时，先分清是方法、
    输入还是环境问题
产物任务结果 + 使用记录
版本、环境、修正
